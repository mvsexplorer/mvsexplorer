# Diagnostic Synthetic Test Dump

Location:

```text
test\test-mvs-dump-diagnostics\
```

This is intentionally inconsistent test data, not representative catalog data.

It contains designed positive cases for every 0.7.0 duplicate/orphan finder:

- duplicate IDs in all requested ID-bearing/literal-ID sources;
- duplicate titles in each requested title-bearing source;
- duplicate release dates;
- duplicate filenames in `mvs.txt` and `mvs_names.txt`;
- source-exclusive IDs/titles in each major text source;
- filename differences between `mvs.txt`, `mvs_names.txt`, SHA-1, and SHA-256;
- two artificial note headings with `[ID: 601]` solely to exercise the
  requested notes-ID duplicate finder.

Exact expected stdout is stored under:

```text
test\expected-diagnostics\
```

The expected outputs are generated by an independent Python reference parser:

```text
dev\generate_expected_diagnostic_outputs.py
```

The public diagnostic `.bat` tools are not invoked when expected outputs are
generated. This avoids making the regression oracle depend on the code under
test.

Run:

```text
test\test_diagnostic_tools.bat
```

to execute all diagnostic tools against the fixture.

The full suite:

```text
test\test_all.bat path_to_real_mvs_dump_folder
```

uses the real dump for scalar/lookup regression and the synthetic dump for
diagnostic regression.
