# Archive change-history and all-ever tools

> **0.19.0 layout:** Public utility BATs referenced in this document are delivered under `tools\`. Run them as `tools\<tool>.bat` from the project root, or change into `tools\` first. Their established arguments/output semantics are unchanged.


Version 0.11.0 adds two archive-wide builders on top of the 0.10.0 source-local
comparison model.

## Tools

```text
build_mvs_dump_change_history.bat mvs-dumps-root output-folder
build_mvs_dump_all_ever.bat       mvs-dumps-root output-folder
```

Both public batch files are fully standalone. The archive root must contain
snapshot directories named like `mvs_YYYY-MM-DD`, optionally with `-HHMM`
and/or `_N` suffixes. A wrapper directory named `mvs_dumps_archive` is also
recognized.

For each snapshot, source files are resolved first at the snapshot root and
then under `snapshot\mvs_dmp\`. This covers the known nested layout used by
`mvs_2020-08-20` and `mvs_2020-08-27` without turning those snapshots into
false coverage gaps.

Snapshot ordering is chronological from the snapshot directory name. Same-day
entries use the optional HHMM value, then numeric `_N` revision, then name as
a deterministic tie-break.

## Change-history output

`build_mvs_dump_change_history.bat` creates:

```text
output-folder\
  added\
    <domain>.tsv
  removed\
    <domain>.tsv
  history-snapshots.tsv
  history-coverage.tsv
```

There are 19 `<domain>.tsv` files under both `added` and `removed`, one for
every 0.10.0 comparison domain/source.

Each ledger has:

```text
from_dump    to_dump    value
```

For every adjacent snapshot pair, values in the earlier source but not the
later source are appended to `removed`; values only in the later source are
appended to `added`. Ordering remains transition order followed by source
order, matching the comparison tools.

## Missing source files are coverage gaps

A missing source is **not** an empty set.

For an adjacent pair where either side lacks a required source, no additions or
removals are inferred for any domain using that source. Instead,
`history-coverage.tsv` records one of:

```text
compared
missing-first
missing-second
missing-both
```

This is essential for real archive history because early snapshots do not all
contain the same source files. Treating source introduction as an empty-to-full
comparison would manufacture a mass addition that is really a coverage change.

## All-ever output

`build_mvs_dump_all_ever.bat` creates:

```text
output-folder\
  all-ever\
    <domain>.tsv
  all-ever-snapshots.tsv
  all-ever-coverage.tsv
```

Each all-ever domain file contains:

```text
first_seen_dump    last_seen_dump    observed_snapshots    value
```

The union is seeded from the first snapshot where that source is present and
then accumulates every newly observed normalized value. Values are never
deleted from this union, even if later snapshots remove them.

This means a value present in the oldest snapshot is not lost merely because
it has no earlier "addition" event. The resulting file is the most complete
source-local set observed anywhere in the supplied archive.

`observed_snapshots` counts snapshots in which the normalized value was
present. `first_seen_dump` and `last_seen_dump` retain provenance for later
timeline work.

## Domains

The 19 domains are exactly the existing comparison matrix:

- IDs from `mvs.txt`, `mvs_ids.txt`, `mvs_names.txt`, `mvs_dates.txt`
- titles from those same four sources
- dates from `mvs_dates.txt`
- SHA-1 from `mvs.txt`, `mvs_names.txt`, `mvs.sha1`
- SHA-256 from `mvs.txt`, `mvs_names.txt`, `mvs.sha256`
- filenames from `mvs.txt`, `mvs_names.txt`, `mvs.sha1`, `mvs.sha256`

The normalizations are the same as the compare tools. In particular,
`mvs_names.txt` IDs remain textual and source-local; they are not silently
merged with numeric product-ID domains.

## Running both builders

The two tools may safely target the same output folder:

```bat
build_mvs_dump_change_history.bat C:\data\mvs_dumps_archive C:\data\mvs-history
build_mvs_dump_all_ever.bat       C:\data\mvs_dumps_archive C:\data\mvs-history
```

The all-ever builder replaces only its own `all-ever\` output and its two
all-ever metadata files. It leaves `added\` and `removed\` intact.

## Return codes

```text
0  success/help
2  invalid/missing arguments or unsupported embedded mode
3  archive root not found or contains no recognized snapshots
4  insufficient recognized snapshots
5  parse/runtime/output failure
```

## Regression tests

```text
test\test_history_tools.bat
```

The synthetic archive has three snapshots. It forces removal, addition,
reintroduction, and stable normalized values across all 19 domains. Fixed
expected files are generated by an independent Python parser that never invokes
the public batch tools.
